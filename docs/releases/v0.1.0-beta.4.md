# estrobo v0.1.0-beta.4

**English** | [Español](https://github.com/loomitz/estrobo/blob/main/docs/releases/v0.1.0-beta.4.es.md)

Estrobo's third limited public beta for macOS adds compact menu-bar controls and hardens Bluetooth input, heartbeat handling, and termination safety.

> [!IMPORTANT]
> This official beta 4 build is the exact universal DMG signed with Apple Developer ID, notarized and stapled by Apple, accepted by Gatekeeper, and verified through the coordinated release gates. Download it only from this public GitHub prerelease and verify its checksum files.

> [!CAUTION]
> Connecting still applies Estrobo's local A0/A1 state to the trigger; it does not import the trigger's current state. Review the groups and values shown before connecting. Bluetooth acknowledgement does not prove an optical result.

## What's new

- Optional compact controls in the macOS menu bar for each visible workspace group.
- Group on/off, one-third-EV Manual power steps, direct power selection, and safe pending-change controls without opening the full workspace.
- A guarded global Test action in the compact panel, plus one subtle global settings-update status instead of repeated per-group notices.
- A persistent setting to hide the menu-bar icon and restore it later from Settings.
- Explicit pre-connect disclosure that Estrobo overwrites A0/A1 from its local workspace.
- Termination protection while Sync, Apply, Test, a gesture, debounce, restoration, or another physical operation is pending.
- Coalesced `FEC8` heartbeat replies: one in-flight intent and one deadline per session, with deterministic completion, failure, timeout, and disconnect cleanup.
- Canonicalized Bluetooth device names that reject control, format, bidi, terminal-escape, and default-ignorable Unicode before names reach compatibility checks, persistence, logs, or UI.
- An automated launch-responsiveness check and accessibility contract, plus a documented manual native AX smoke covering localized button/menu roles, values, hints, disabled states, and adjustable power actions.

## Menu-bar behavior

The compact panel uses the same controller, drafts, delivery mode, and Bluetooth session as the full app. It is another presentation of the current workspace, not an independent connection.

Only visible workspace groups appear. On/off and Manual power changes follow the selected automatic or button-driven delivery mode. Pending changes use one compact global status and can be applied or discarded from the panel only when every affected field is represented there; advanced, Multi, recovery, or hidden-group work must be reviewed in the full app.

Test fires the active trigger groups with the already-applied settings. It is disabled while settings are pending, Sync or another physical operation is in progress, Standby is active, or recovery is required. Bluetooth delivery does not confirm an optical flash.

Standby, recovery, unsupported modes, an incomplete session, and power limits disable the affected controls with a localized reason. Hiding the icon does not quit Estrobo; restore it from Settings.

## Hardware compatibility

Estrobo connects over Bluetooth to a compatible Godox flash trigger. It does not connect directly to flashes or receivers; they continue to communicate through the trigger's Godox radio system.

The trigger must have built-in Bluetooth enabled and expose the Godox Flash BLE/GATT profile supported by Estrobo. A Bluetooth advertisement or Godox-like name alone is not proof of compatibility.

The documented physical matrix remains a Godox X3Pro trigger and Godox AD400Pro II flash units. The exact camera variant and firmware revisions were not recorded. Other triggers, flashes, firmware combinations, and every optical result still require physical validation.

## Privacy and security

- No Estrobo account, backend, network entitlement, analytics, or telemetry.
- App Sandbox and Bluetooth entitlement enabled.
- Remembering a transmitter and Radio Code remains opt-in and starts off.
- Remembered names, UUIDs, and codes stay local and unencrypted; the six-digit Radio Code is a low-value trigger PIN and should not be reused elsewhere.
- Device names are normalized and rejected when they contain invisible, directional, terminal, or control characters that could make one trigger look like another or alter terminal output.

## Remaining limits

There is no complete trigger-to-app readback. Connecting and Sync deliberately write the local A0 and configured A1 values. `FEC8` does not identify a group, return the applied value, or prove that a flash fired.

Channel changes, non-neutral TTL compensation, Radio Code changes, firmware, and OAD remain unavailable. TTL, Beep, Standby, fixed modeling intensities, Multi limits, and optical behavior remain dependent on model and firmware validation.

Read [Automatic synchronization](https://github.com/loomitz/estrobo/blob/v0.1.0-beta.4/docs/AUTOMATIC-SYNC.md) before connecting hardware.

## Download and verify

1. Download `estrobo-v0.1.0-beta.4-macos-universal.dmg`, `SHA256SUMS`, and `estrobo-v0.1.0-beta.4-manifest.json` from this GitHub Release only.
2. Keep the three files together and run `shasum -a 256 -c SHA256SUMS`. Continue only if the DMG and manifest both report `OK`.
3. Open the DMG, drag Estrobo to Applications, eject the image, and launch the installed copy.
4. Do not bypass Gatekeeper or remove quarantine. If verification fails, delete the copy and download it again from the official release.

```sh
shasum -a 256 -c SHA256SUMS
spctl --assess --type open --verbose=4 \
  --context context:primary-signature \
  estrobo-v0.1.0-beta.4-macos-universal.dmg
codesign --verify --deep --strict --verbose=2 /Applications/estrobo.app
spctl --assess --type execute --verbose=4 /Applications/estrobo.app
```

The release manifest is the authoritative record of the tag, commit, architectures, minimum macOS version, Developer ID identity, notarization submissions, and exact DMG digest.
